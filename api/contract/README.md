# API contract — Trip Management

The HTTP contract of this backend, one file per module, written for building the React front end. It describes what the API **does today**; `src/` is the source of truth and this folder must be updated in the same change as any fix or feature that touches an endpoint, a DTO, a response shape, a validation rule or an error (see [Keeping it up to date](#keeping-it-up-to-date)).

Last updated: **2026-11-09** (Story 14, trip contract number).

Use it to generate TypeScript types or an API client (for example `npx openapi-typescript contract/openapi.json -o src/api/schema.ts`). The markdown files add what OpenAPI cannot express: business rules, error messages and real examples.

## Conventions (all modules)

### Base URL, CORS and docs

- Every route is under the global prefix **`/api`**. Local default: `http://localhost:3000/api`.
- **CORS is not enabled** in `src/main.ts`. In development, proxy `/api` from the front-end dev server to `http://localhost:3000` (for Vite: `server.proxy = { '/api': 'http://localhost:3000' }`) and call relative paths like `/api/trips`. The relative file urls below (`/api/files/:id/download`) then resolve against the same origin.
- Swagger UI: `/api/docs` (click **Authorize** and paste the access token); OpenAPI JSON: `/api/docs-json` (not served when `NODE_ENV=production`).

### Authentication

Details in [auth.md](auth.md).

- `POST /api/auth/login` with `{ email, password }` → `{ accessToken, tokenType: "Bearer", expiresIn, user }`.
- **Every endpoint needs `Authorization: Bearer <accessToken>`** except `GET /api/health` and `POST /api/auth/login`. File downloads included.
- 401 messages: `Missing access token` (no / non-Bearer header) and `Invalid or expired access token` (bad, expired, or the user was deleted or deactivated).
- No refresh token: on any 401 send the user to the login page.
- Roles (`admin` / `user`) are returned but **not enforced** by the API yet.

### Data types

| Kind | Format | Example |
|------|--------|---------|
| Ids | UUID v4 string | `"4547f27b-3db8-416c-811a-1cdb7f972894"` |
| Timestamps (`createdAt`, `updatedAt`, `inspectedAt`) | ISO 8601 UTC string | `"2026-10-31T18:44:48.228Z"` |
| Dates (trip `date`) | `"YYYY-MM-DD"` string | `"2026-11-15"` |
| Times (trip `time`) | send `"HH:mm"` or `"HH:mm:ss"`, always returned as `"HH:mm:ss"` | `"08:30:00"` |
| File urls | path relative to the API host | `"/api/files/aa569ad1-ff2a-4e18-aeae-2b0fa5e50f6e/download"` |

Path `:id` parameters must be UUIDs; anything else returns **400** `Validation failed (uuid is expected)`.

### Request bodies

- JSON (`Content-Type: application/json`), except file upload (`multipart/form-data`).
- **Unknown properties are rejected** with 400 `property <name> should not exist`. Send only the documented fields; never send `id`, `createdAt`, `updatedAt` or read-only fields like a trip's `qrCodeUrl`.
- String fields are **trimmed** before validation where noted (all name/code fields).
- **Create** (`POST`): required fields must be present.
- **Update** (`PATCH`): every field is optional. **Omitted = unchanged.** `null` is **rejected** (400) unless the field is documented as nullable (then `null` clears it).

### Lists and pagination

Paginated list endpoints (`companies`, `countries`, `vehicles`, `drivers`, `trips`) accept:

| Query | Type | Default | Rules |
|-------|------|---------|-------|
| `page` | integer | `1` | ≥ 1 |
| `limit` | integer | `10` | 1–100 |
| `search` | string | — | trimmed, 1–100 chars, case-insensitive partial match on the module's searchable fields |

and return:

```json
{
  "data": [ /* items */ ],
  "meta": { "page": 1, "limit": 10, "total": 249, "totalPages": 25 }
}
```

`users`, `files` (by owner) and `inspection-indicators` return a plain array (not paginated).

### Deleting

`DELETE` returns **204** with no body. Every business resource is **soft-deleted**: it disappears from lists and `GET :id` returns 404, but rows that reference it keep working. Users are the exception (hard delete).

### Errors

Every error has the same body:

```json
{
  "statusCode": 400,
  "error": "Bad Request",
  "message": [
    "nameAr must be longer than or equal to 2 characters",
    "nameAr must be a string"
  ],
  "path": "/api/countries",
  "timestamp": "2026-10-31T21:53:39.278Z"
}
```

`message` is an **array** for validation errors (one entry per failed rule, nested fields use dotted paths like `inspection.results.0.status must be a boolean value`) and a **string** otherwise:

```json
{
  "statusCode": 404,
  "error": "Not Found",
  "message": "Trip 00000000-0000-4000-8000-000000000000 not found",
  "path": "/api/trips/00000000-0000-4000-8000-000000000000",
  "timestamp": "2026-10-31T21:53:39.235Z"
}
```

| Status | When |
|--------|------|
| 400 | Validation failed, bad UUID, a referenced id does not exist, business rule broken |
| 401 | No / invalid / expired token on a protected route; wrong credentials on login; wrong current password on change-password |
| 404 | The resource in the path does not exist (or is soft-deleted) |
| 409 | Unique value already used (each module lists which); generic DB unique violation → `"Resource already exists"` |
| 413 | Uploaded file too large |
| 415 | Uploaded file type not allowed |
| 500 | `"Internal server error"` |

### Upload-first file flow

Images are uploaded **before** the record that uses them:

1. `POST /api/files` (multipart) with `ownerType` (e.g. `companies`) and no `ownerId` → response `url`.
2. Send that `url` in the owning resource's body (e.g. a company's `headerUrl`). The backend checks it and links the file to the record.
3. Show images by fetching `url` **with the token** and using `URL.createObjectURL(blob)` as the `<img src>`; a plain `<img src={url}>` gets 401 (see [files.md](files.md#get-apifilesiddownload)).

Trip QR codes are the opposite: the backend creates the file itself and returns `qrCodeUrl`.

## Keeping it up to date

Rule for every fix or feature (also in `CLAUDE.md`): **if the change touches the HTTP surface, update `contract/` in the same change.**

1. Edit the module file: endpoint table, request fields and rules, response example, errors.
2. New module → new `<module>.md` from the same layout, plus a row in the Modules table above.
3. Regenerate `openapi.json` with the app running in development:
   `curl -s http://localhost:3000/api/docs-json -o contract/openapi.json`
4. Add a line to the [Changelog](#changelog) and bump **Last updated**.

Each module file uses the same layout: Endpoints table → shared types (TypeScript) → one section per endpoint (request, rules, response example, errors).
